# The read log: a third persistence class

Text skip and the Timeline both need to know what the player has already read, and that puts a third kind of file beside the save slots ([ADR 0006](0006-save-slots-on-disk-format-and-version-policy.md)) and the settings file ([ADR 0007](0007-settings-file-beside-the-pack.md)). Three choices are hard to reverse once players have files on disk: **what a read line is keyed by**, **what a version mismatch means**, and **which crate owns the format**. The pre-beta plan of 2026-10-01 proposed a versioned `<pack-dir>.read.ron` keyed by `(scene_id, pc)`; the follow-up decision kept the file, its per-pack scope and its atomic write, and changed the key, the failure posture and the ownership on the code facts — `runner.rs` increments `pc` before parking, `Scene.line_numbers` records an authored source line for every `Line`, `save.rs` owns the slot format while the app drives when it writes, and `failure.rs` derives every failure's surface from its numbered inventory.

**Decision.** The read log is `<pack-dir>.read.ron` — a sibling of the pack directory, named after it, RON, one file per pack — written atomically (temp sibling plus rename). It holds `version: 1`, `read: BTreeMap<scene id, sorted authored source lines>` and `visited: sorted scene ids`. A line key is **`(scene id, authored source line)`** — `Scene.line_numbers[pc - 1]` at a say-park — not the runner's `pc`. A say-line is **marked read the moment play parks on it**, with an **arrival-status** boolean captured before the mark so seen-skip's gate can still stop at a line the player has never seen. A scene is **visited when it becomes the live play scene** — play entry (New Game, Continue), a cross-scene jump, or a load's restored scene — never by the boot park behind the title. The app drives the lifecycle: read once per launch after the pack loads; flush at play entry, a crossing, a choice resolve, a decision resolve (model **or** fallback) and app exit, dirty-gated, one atomic write. The version policy is **strict equality**: any file that is absent, undecodable, wrongly versioned (older or newer) or unreadable is the empty log — never an error, never a Notice, never deleted, overwritten by the next dirty flush. IO failures take the [runtime failure posture](../runtime-hardening.md#runtime-failure-posture)'s **Continue-silently** posture as one new numbered row (`warn!` only, no Notice). The format, the path and the IO live in `engine/src/read_log.rs`, mirroring `save.rs` — `READ_LOG_VERSION`, `ReadLog`, `read_log_path_for`, `load_read_log`, `write_read_log`, `ReadLogError` — and the shared sibling naming rule and atomic write idiom live in `engine/src/sidecar.rs` (`sibling_path`, `write_atomic`); the app owns the marks, the arrival status, the dirty flag and the flush moments. `.gitignore` gains `*.read.ron` beside `*.save.ron` and `*.settings.ron`.

Why a third class: a save is player data — preserved, never auto-deleted, and given an **additive version floor** so old files keep loading; a preference is a reproducible value — unversioned, permissive on read and lossy on rewrite ([ADR 0007](0007-settings-file-beside-the-pack.md)). Read marks are neither. They are **knowledge**: cheap to lose (the player re-reads a line) but dangerous to misread (skip would skip unseen text). The file therefore keeps the save's durable, versioned, pack-sibling shape and the settings file's discard-on-mismatch posture: a version mismatch is not a migration problem, it is "everything unread".

## Considered options

- **`(scene_id, pc)` keys** — the plan's proposal. Rejected: `pc` is a position in the parsed `lines` vector whose say-park value carries the increment-before-park offset that every reader would have to remember, and the read log has no reason to share a save's coordinate space. The authored source line is the coordinate the author wrote and the one a human can check in `read.ron`. The edit fragility is the same class either way — a mid-scene insertion can hand a new line a previously-read key, deletion mostly re-locks — so the tiebreaker is legibility, and the residual is recorded either way.
- **The parked line's own index (`pc - 1`).** Rejected: identical to the key above with one less offset, but still a parsed-vector coordinate rather than an authored one.
- **A rendered-text fingerprint (`(scene, speaker, interpolated text)`).** Rejected as the safe-but-heavy alternative: it survives edits and re-interpolation perfectly (new or changed text is always unread, so a fresh line can never be false-read), but the file becomes opaque or stores whole prose, duplicate identical renderings collapse into one entry, and a stable hash becomes part of the format contract. It is the first candidate if the demo's edit churn ever makes the false-read residual bite.
- **Marking on the advance that leaves the line.** Rejected: it is the conservative rule — a quit while parked re-shows the line next session — but it makes a fully-read-then-quit session's last line "new" and forces the skip gate to explain why the line on screen is unread. A displayed line is knowledge; the arrival status keeps the gate honest.
- **The boot park counting as a visit.** Rejected: launching the app and looking at the title would unlock the opening scene with no play.
- **No flush on a fallback-resolved decision.** Rejected: it mirrors the autosave's churn rule exactly, but a transient API outage would cost the player the marks for lines they saw. A checkpoint and a piece of knowledge answer different questions ([`docs/runtime-hardening.md` § Save slots §4](../runtime-hardening.md#save-slots)).
- **App-side ownership (`app/src/read_log.rs` beside `settings.rs`).** Rejected: ADR 0007's reason for app-side settings was that preferences are presentation state the headless runner never reads; the read log is durable, versioned, per-pack progress — the save's side of that line — and putting both versioned classes in `engine/` keeps the schema and the version policy testable without Bevy.
- **An engine-owned format with an app-derived path.** Rejected: it splits the sibling naming from the format exactly where `save_path_for` already says the engine owns it, and leaves two derivations of the same convention to drift.
- **An additive version floor (ADR 0006's rule).** Rejected: a partially-understood old key set is the very failure the log exists to prevent, and there is no checkpoint to preserve — the payload is regenerable by playing.
- **A newer-versioned file left read-only for the session.** Rejected: it strands this session's marks forever to protect a future build's regenerable knowledge.
- **A numbered row per side, or no row at all.** Rejected: one row for the file's IO keeps the inventory total without two rows that share posture, level and surface; no row would put the only failure sites outside `failure::report` and its table-driven test.

## Consequences

- New Game does not reset the read log, so it re-locks neither skip nor the Timeline ([`docs/title-and-menu.md` § Title §3](../title-and-menu.md#title)).
- Bumping `READ_LOG_VERSION` re-locks every line and every scene; there is no migration path, by design.
- An edit that inserts a line above already-read lines can mark the new line read; deletion and reordering mostly re-lock. This residual is recorded, and it is the trigger to revisit the fingerprint key.
- A crash between flushes loses at most the marks since the last one — the current scene's progress.
- `.gitignore` gains `*.read.ron`; the pack directory stays pristine.
- The [runtime failure posture](../runtime-hardening.md#runtime-failure-posture)'s inventory grows to 26 rows: §2's table, §5's short strings, §6's level table, `FailureRow::ALL` and its table-driven test carry the dated amendment.
- The read log uses the engine-owned shared sidecar naming/write operations; no `SaveFile`/`SAVE_VERSION`, runner, parser or DSL change follows from this read-log decision.
- The [Text skip](../runtime-hardening.md#text-skip) section consumes the mark rule and the arrival status; the [Timeline](../title-and-menu.md#timeline) section consumes the visited set.
- Build-ready detail — the schema, the engine API, the lifecycle, the flush points and the test list — is in [`docs/runtime-hardening.md` § Read log](../runtime-hardening.md#read-log).

## Amendment (2026-10-08, force-skip mark exemption and arrival status)

The skip section answers the mark question this ADR left in the read-log section's hands: a **force-skip advance is exempt from mark-at-park** — text blown past stays unread, so a later seen skip still stops there — while force-skip parks still evaluate the arrival status and the scenes they cross are still marked visited. The exemption attaches to the advance, not the line: a later manual park on the same line marks normally. Seen skip changes nothing here, since it only ever passes lines already marked. The **arrival status is restated as an invariant**: the app derives it from the log at each park transition, before that frame's mark lands, and holds it for that park's duration only — never across a park change, a load, a New Game or a Timeline jump. The full rules — the two controls, the step, the gate and the test list — are in [`docs/runtime-hardening.md` § Text skip](../runtime-hardening.md#text-skip).

## Amendment (2026-10-14, shared sibling owner)

The Decision and Consequences now name the landed shared owner: `engine/src/sidecar.rs` supplies `sibling_path` and `write_atomic` to the read log, save slots and app settings. The former `save.rs::pack_sibling` helper was removed rather than retained as a `pub(crate)` sharing point. The read-log format, path API and IO remain in `engine/src/read_log.rs`; the app still owns marking, arrival status and flush timing. This ownership correction mirrors [ADR 0007's ownership amendment](0007-settings-file-beside-the-pack.md) and changes no key, version, schema, lifecycle or failure policy.
